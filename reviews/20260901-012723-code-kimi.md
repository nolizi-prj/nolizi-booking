### Correctness of `support/pg.ts`

- Unique directory: `pumasi-pg-${label}-${pid}-${16 hex}` matched by `OURS = /^pumasi-pg-.+-(\d+)-[0-9a-f]{16}$/` — 8 random bytes = 16 hex chars, consistent. Because each run makes a fresh directory, `initdb` (which `embedded-postgres` calls unconditionally, per the header comment) can no longer meet yesterday's corpse. The latch mechanism named in HEAD's log — "the directory alone is sufficient" — is genuinely closed, not merely the orphaned-process half.
- `sweepStale()` only removes directories whose *creator pid* is dead, and only after `reapServer()` confirms no live server holds them. Creator-alive → skip. This correctly avoids deleting a concurrent run's data.
- `reapServer()`'s pid-reuse handling is the load-bearing edge case and it is handled properly: a live pid from `postmaster.pid` is only SIGINTed after `/proc/<pid>/cmdline` is read and shown to name *this exact directory*; unreadable or mismatched → refuse to reap (litter, never corruption). `alive()` treats `EPERM` as alive. On non-Linux (`/proc` absent) it conservatively refuses to reap a live server — safe failure direction.
- Legacy fixed-name directories (`/tmp/pumasi-pg-bootstrap` etc., still named in HEAD's message) are deliberately left alone, as the header comment states — correct, since a concurrent run from an older checkout may hold them.
- Memoized `swept ??= sweepStale()` shares one sweep across files in a process; failure modes in the sweep are all caught (`readdir` → `[]`, `rm`/`reapServer` → `.catch`), so the memoized promise cannot become a poisoned rejection.
